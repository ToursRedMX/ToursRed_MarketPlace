# POR QUE SE TOLERAN, Y CUALES SON HUECO DE VERDAD

# Los caminos SINCRONOS insertan `processor_fee: 0` porque en ese momento no

# procesador. Quien la rellena es el webhook. Eso NO es un bug por si mismo, es
# el patron del repo. Lo que decide si una entrada es un hueco real es si el
# webhook de ESE procesador alcanza la fila que dejo el camino sincrono:
#
#   stripe ......... SI. `stripe-webhook` actualiza por
#                    `stripe_payment_intent_id`, y el update esta FUERA del
#                    `if (!existingTx)`, asi que toca la fila la haya creado
#                    quien la haya creado.
#   mercadopago .... SI, desde el 10-sep-2026. Antes el webhook solo insertaba
#                    "si no existe" y se iba, dejando el 0 para siempre. Se le
#                    agrego la rama que actualiza cuando la fila ya esta.
#   conekta ........ SI. Busca la transaccion y actualiza por su id.
#   openpay ........ NO del todo. Su update filtra por
#                    `charge_context = 'booking_deposit'` Y `status = 'pending'`,
#                    asi que NO alcanza suplementos ni extras. HUECO REAL.
#   paypal ......... SIN VERIFICAR: no se encontro un update de comision en
#                    `paypal-webhook`.
#
